# 发布流程

1. 从干净的公共仓库检出构建，不从个人数据工作区直接打包。构建器要求15条demo、空用户笔记和空工作区。
2. `release/distribution-files.json` 是明确文件清单；新文件必须经审查后纳入，备份、临时目录、宿主配置及个人迁移脚本禁止纳入。
3. `python tools/build-distribution.py --output <工作区内输出目录> --version 1.3.0`。构建器重建页面、核对锁定规则、运行可移植回归，确认缺审阅范围的真实日报发布会失败，再创建ZIP和SHA256。
4. 实际ZIP再次解压后验证全部指纹并运行自检。任何一步失败都不得发布。清单不会包含构建和测试产生的临时输出。
5. 人工或真实浏览器检查首页、日报、全库、计划及窄屏线索墙。保存实际结果后再创建Git标签和Release。

发布包自检与真实日报发布是独立结论；展示demo成功不证明GitHub认证、总体召回或一轮真实日报已经完成。

仓库检出保留原始字节，避免自动换行转换破坏distribution.json指纹或锁定术语表。发布包和标签源代码使用相同字节。
